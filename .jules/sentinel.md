## 2025-03-03 - [Fix JSON-LD XSS]
**Vulnerability:** XSS vulnerability where standard `JSON.stringify` was used in `dangerouslySetInnerHTML` for JSON-LD `<script type="application/ld+json">` tags in `app/blog/[slug]/page.tsx`.
**Learning:** React/Next.js assumes strings inside `dangerouslySetInnerHTML` are safe. Using `JSON.stringify` does not escape `<` or `>` characters, allowing attackers to close the script tag early with `</script>` and execute arbitrary code if malicious content gets into the metadata.
**Prevention:** Always use a utility like `safeJsonStringify` which replaces `<` with `\u003c`, `>` with `\u003e`, and `&` with `\u0026` before injecting JSON into `<script>` tags.
## 2025-02-27 - [Fix XSS vulnerability in video embed URLs]
**Vulnerability:** `getYouTubeEmbedUrl` in `app/db/talks.ts` falls back to returning the unsanitized original URL if it does not match a YouTube format. This URL is then injected directly into an `iframe src` attribute in `TalkLayout.tsx`, allowing potential XSS via malicious URIs like `javascript:`.
**Learning:** React and Next.js do not natively sanitize strings passed to `iframe` `src` attributes. Relying solely on a regex to match expected patterns (like YouTube embeds) and blindly returning the fallback input is dangerous for user-controlled strings.
**Prevention:** Always validate protocols (e.g., ensuring `http:` or `https:`) of external URLs using the native `URL` constructor before injection to prevent XSS vulnerabilities from `javascript:` or `data:` URIs. Use a safe base URL (like `http://localhost`) when parsing to correctly handle and allow safe relative paths.
