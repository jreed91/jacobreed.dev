## 2025-03-03 - [Fix JSON-LD XSS]
**Vulnerability:** XSS vulnerability where standard `JSON.stringify` was used in `dangerouslySetInnerHTML` for JSON-LD `<script type="application/ld+json">` tags in `app/blog/[slug]/page.tsx`.
**Learning:** React/Next.js assumes strings inside `dangerouslySetInnerHTML` are safe. Using `JSON.stringify` does not escape `<` or `>` characters, allowing attackers to close the script tag early with `</script>` and execute arbitrary code if malicious content gets into the metadata.
**Prevention:** Always use a utility like `safeJsonStringify` which replaces `<` with `\u003c`, `>` with `\u003e`, and `&` with `\u0026` before injecting JSON into `<script>` tags.
## 2025-03-03 - [Fix XSS in iframe src from malicious videoUrl]
**Vulnerability:** XSS vulnerability where standard string fallback was used in `getYouTubeEmbedUrl` for non-YouTube URLs. If a talk's `videoUrl` frontmatter contained `javascript:` or `data:` URIs, it would be injected directly into the `iframe` `src` attribute in `TalkLayout.tsx`, allowing arbitrary JavaScript execution.
**Learning:** React and Next.js do not natively sanitize strings passed to `iframe` `src` attributes. A regex check for YouTube URLs is insufficient protection if it falls back to passing the raw user input directly. Empty strings also need careful handling when passed to the `URL` constructor.
**Prevention:** Always validate protocols (e.g., ensuring `http:` or `https:`) of external URLs using the native `URL` constructor before injection to prevent XSS vulnerabilities from unsafe URIs. Reject anything that isn't `http:` or `https:`, returning a safe fallback like `about:blank`.
## 2025-03-03 - [Fix Stored XSS in Link components via slug]
**Vulnerability:** CodeQL flagged a Stored Cross-Site Scripting (XSS) vulnerability. Unsanitized `slug` values from markdown file frontmatter were interpolated directly into Next.js `<Link href={...}>` components and `a` tag `href` attributes across various files (e.g., `TalkCard.tsx`, `BlogPostCard.tsx`, `BlogPost.tsx`, and `BlogLayout.tsx`). This could allow an attacker to inject malicious URLs (like `javascript:`) if they gained control over the markdown source.
**Learning:** Next.js `Link` components and native HTML `<a>` tags do not automatically encode URI components in their `href` attributes. Data originating from files or databases (even statically generated ones) must be treated as untrusted input and properly sanitized or encoded before use in structural attributes like URLs.
**Prevention:** Always sanitize file-derived or database-derived variables like `slug` using `encodeURIComponent()` when interpolating them into URL paths to satisfy security compliance checks and prevent injection attacks.
