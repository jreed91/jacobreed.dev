## 2025-03-03 - [Fix JSON-LD XSS]
**Vulnerability:** XSS vulnerability where standard `JSON.stringify` was used in `dangerouslySetInnerHTML` for JSON-LD `<script type="application/ld+json">` tags in `app/blog/[slug]/page.tsx`.
**Learning:** React/Next.js assumes strings inside `dangerouslySetInnerHTML` are safe. Using `JSON.stringify` does not escape `<` or `>` characters, allowing attackers to close the script tag early with `</script>` and execute arbitrary code if malicious content gets into the metadata.
**Prevention:** Always use a utility like `safeJsonStringify` which replaces `<` with `\u003c`, `>` with `\u003e`, and `&` with `\u0026` before injecting JSON into `<script>` tags.

## 2025-02-20 - [Fix XSS via unsafe iframe src in Talks]
**Vulnerability:** XSS vulnerability where `getYouTubeEmbedUrl` in `app/db/talks.ts` returned unsanitized fallback URLs directly to an `iframe`'s `src` attribute in `app/components/TalkLayout.tsx`. If an attacker provided a `javascript:` or `data:` URI in the MDX `videoUrl` frontmatter, it could lead to arbitrary script execution when the talk page is rendered.
**Learning:** `iframe` `src` attributes are execution contexts. When binding dynamically provided URLs to `iframe src`, the protocol must be strictly validated to prevent execution of malicious code, specifically preventing `javascript:` and `data:` protocols while allowing standard HTTP/HTTPS protocols. The `URL` constructor's protocol parser should be used rather than naive substring matching to prevent bypasses.
**Prevention:** Always validate and sanitize URLs provided from potentially untrusted sources (like user input or MDX frontmatter) before using them in sensitive contexts like `iframe src` or `a href`. Use `new URL()` to correctly parse and check protocols instead of Regex. For fallback cases, return `about:blank` or a relative path instead of the raw input.
