## 2025-03-03 - [Fix JSON-LD XSS]
**Vulnerability:** XSS vulnerability where standard `JSON.stringify` was used in `dangerouslySetInnerHTML` for JSON-LD `<script type="application/ld+json">` tags in `app/blog/[slug]/page.tsx`.
**Learning:** React/Next.js assumes strings inside `dangerouslySetInnerHTML` are safe. Using `JSON.stringify` does not escape `<` or `>` characters, allowing attackers to close the script tag early with `</script>` and execute arbitrary code if malicious content gets into the metadata.
**Prevention:** Always use a utility like `safeJsonStringify` which replaces `<` with `\u003c`, `>` with `\u003e`, and `&` with `\u0026` before injecting JSON into `<script>` tags.
## 2025-02-18 - [Prevent Stored XSS via File-Derived Slugs in Links]
**Vulnerability:** File-derived variables like `slug` from MDX metadata were interpolated directly into Next.js `<Link href={...}>` components (e.g., in `TalkCard.tsx`, `BlogPostCard.tsx`, `BlogPost.tsx`) and external anchor tags (e.g., `BlogLayout.tsx` edit/discuss URLs) without sanitization. This presents a stored cross-site scripting (XSS) risk if a maliciously crafted filename is processed, violating security rules detected by CodeQL.
**Learning:** Even internal file names/slugs should be treated as untrusted input when injected into `href` attributes, as they can contain characters that break out of the URL context or form harmful URIs if intentionally tampered with on the filesystem.
**Prevention:** Always sanitize file-derived variables used in URLs (like `talk.slug` and `blog.slug`) using `encodeURIComponent()` when interpolating them into Next.js `<Link href={...}>` or standard `<a>` tags.
