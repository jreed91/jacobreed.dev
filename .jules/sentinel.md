## 2025-03-03 - [Fix JSON-LD XSS]
**Vulnerability:** XSS vulnerability where standard `JSON.stringify` was used in `dangerouslySetInnerHTML` for JSON-LD `<script type="application/ld+json">` tags in `app/blog/[slug]/page.tsx`.
**Learning:** React/Next.js assumes strings inside `dangerouslySetInnerHTML` are safe. Using `JSON.stringify` does not escape `<` or `>` characters, allowing attackers to close the script tag early with `</script>` and execute arbitrary code if malicious content gets into the metadata.
**Prevention:** Always use a utility like `safeJsonStringify` which replaces `<` with `\u003c`, `>` with `\u003e`, and `&` with `\u0026` before injecting JSON into `<script>` tags.

## 2024-05-20 - [Stored XSS via MDX Frontmatter URLs]
**Vulnerability:** The `getYouTubeEmbedUrl` function in `app/db/talks.ts` fell back to returning raw, unsanitized input URLs from MDX file frontmatter if they did not match the YouTube URL format. These fallback strings were passed directly into the `src` attribute of an `iframe` in `app/components/TalkLayout.tsx`. This exposed the application to Stored XSS via unsafe protocols (e.g. `javascript:alert(1)`) present in MDX `videoUrl` metadata.
**Learning:** Even statically generated content engines reading from local markdown/MDX files are vulnerable to stored XSS if their layout components bind unsanitized frontmatter properties to sensitive attributes like `src` or `href`. The "source" of input may appear safe because it's in the repo, but malicious actors can submit PRs modifying those files or the app could eventually dynamically load MDX content.
**Prevention:** Always validate and enforce safe protocols (`http:`, `https:`) for dynamic links and sources originating from external inputs (including local configuration/markdown files). The native `URL` constructor with a valid base URL cleanly extracts protocols avoiding regex parsing gaps, and safely resolves relative URLs.
