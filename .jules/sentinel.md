## 2025-03-03 - [Fix JSON-LD XSS]
**Vulnerability:** XSS vulnerability where standard `JSON.stringify` was used in `dangerouslySetInnerHTML` for JSON-LD `<script type="application/ld+json">` tags in `app/blog/[slug]/page.tsx`.
**Learning:** React/Next.js assumes strings inside `dangerouslySetInnerHTML` are safe. Using `JSON.stringify` does not escape `<` or `>` characters, allowing attackers to close the script tag early with `</script>` and execute arbitrary code if malicious content gets into the metadata.
**Prevention:** Always use a utility like `safeJsonStringify` which replaces `<` with `\u003c`, `>` with `\u003e`, and `&` with `\u0026` before injecting JSON into `<script>` tags.
## 2026-05-22 - [JSON.stringify undefined return and insufficient escaping XSS]
**Vulnerability:** The `safeJsonStringify` utility failed to handle `undefined` inputs (which causes `JSON.stringify` to return `undefined` rather than a string), leading to a `TypeError` when calling `.replace()`. It also insufficiently escaped forward slashes (`/`), line separators (`\u2028`), and paragraph separators (`\u2029`).
**Learning:** Returning `undefined` directly unhandled from `JSON.stringify` results in DoS by application crash. The lack of slash escaping can allow `<script>` injection, and line/paragraph separators within `<script>` tag JSON payloads cause syntax errors breaking page rendering or functionality.
**Prevention:** Always validate or default the output of `JSON.stringify` if it might operate on `undefined`. Always escape `/`, `\u2028`, and `\u2029` alongside `<` , `>`, and `&` for safely embedding JSON in HTML `<script>` tags.
