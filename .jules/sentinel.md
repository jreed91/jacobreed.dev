## 2025-03-03 - [Fix JSON-LD XSS]
**Vulnerability:** XSS vulnerability where standard `JSON.stringify` was used in `dangerouslySetInnerHTML` for JSON-LD `<script type="application/ld+json">` tags in `app/blog/[slug]/page.tsx`.
**Learning:** React/Next.js assumes strings inside `dangerouslySetInnerHTML` are safe. Using `JSON.stringify` does not escape `<` or `>` characters, allowing attackers to close the script tag early with `</script>` and execute arbitrary code if malicious content gets into the metadata.
**Prevention:** Always use a utility like `safeJsonStringify` which replaces `<` with `\u003c`, `>` with `\u003e`, and `&` with `\u0026` before injecting JSON into `<script>` tags.

## 2024-05-24 - [Iframe Source XSS via Unsafe Fallback Protocol]
**Vulnerability:** The `getYouTubeEmbedUrl` function returned the raw `videoUrl` directly if it didn't match the YouTube regex. This fallback was passed directly to the `src` attribute of an `iframe` in `app/components/TalkLayout.tsx`. If an attacker injected a payload via MDX frontmatter (e.g. `javascript:alert(document.cookie)`), it would execute in the context of the user's browser, leading to Stored XSS.
**Learning:** Even fallback logic for external embeds (like YouTube) needs strict protocol validation. Bypassing regexes doesn't mean the remaining input is safe; it often means it is entirely uncontrolled. Furthermore, correctly parsing the URL (using `new URL()`) allows for robust protocol extraction compared to basic string checks.
**Prevention:** Always validate protocols (e.g., `http:`, `https:`) of URLs interpolated into unsafe contexts like `iframe` `src` or `a` `href`. Use the native `URL` constructor to accurately parse properties, and explicitly handle errors and invalid protocols by returning safe fallbacks like `'about:blank'`.
