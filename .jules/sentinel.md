## 2025-03-03 - [Fix JSON-LD XSS]
**Vulnerability:** XSS vulnerability where standard `JSON.stringify` was used in `dangerouslySetInnerHTML` for JSON-LD `<script type="application/ld+json">` tags in `app/blog/[slug]/page.tsx`.
**Learning:** React/Next.js assumes strings inside `dangerouslySetInnerHTML` are safe. Using `JSON.stringify` does not escape `<` or `>` characters, allowing attackers to close the script tag early with `</script>` and execute arbitrary code if malicious content gets into the metadata.
**Prevention:** Always use a utility like `safeJsonStringify` which replaces `<` with `\u003c`, `>` with `\u003e`, and `&` with `\u0026` before injecting JSON into `<script>` tags.
## 2025-02-23 - [XSS via Iframe src from Content Frontmatter]
**Vulnerability:** The `getYouTubeEmbedUrl` function accepted raw `videoUrl` values from MDX frontmatter and directly injected them into the `src` attribute of an `iframe` in `app/components/TalkLayout.tsx` without protocol validation if they didn't match the YouTube Regex. This allowed execution of malicious `javascript:` or `data:` URIs.
**Learning:** Even content intended for display as rich media URLs (like embedded videos) can be leveraged for XSS if user-controlled input (or markdown frontmatter) is trusted blindly. Regex matching for known good patterns (like YouTube URLs) isn't sufficient if the function falls back to returning the unvalidated string.
**Prevention:** Always parse untrusted URLs using the native `URL` constructor (e.g., `new URL(videoUrl, 'http://localhost')`) to reliably inspect and enforce safe protocols (`http:`, `https:`) before rendering them dynamically, specifically on attributes like `src` or `href`.
