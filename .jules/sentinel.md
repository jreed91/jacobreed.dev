## 2025-03-03 - [Fix JSON-LD XSS]
**Vulnerability:** XSS vulnerability where standard `JSON.stringify` was used in `dangerouslySetInnerHTML` for JSON-LD `<script type="application/ld+json">` tags in `app/blog/[slug]/page.tsx`.
**Learning:** React/Next.js assumes strings inside `dangerouslySetInnerHTML` are safe. Using `JSON.stringify` does not escape `<` or `>` characters, allowing attackers to close the script tag early with `</script>` and execute arbitrary code if malicious content gets into the metadata.
**Prevention:** Always use a utility like `safeJsonStringify` which replaces `<` with `\u003c`, `>` with `\u003e`, and `&` with `\u0026` before injecting JSON into `<script>` tags.
## 2023-10-27 - [XSS in YouTube iframe embed]
**Vulnerability:** The `getYouTubeEmbedUrl` function in `app/db/talks.ts` directly returned unvalidated user input (`talk.metadata.videoUrl`) if it didn't match a YouTube URL pattern. This returned value was then used as the `src` attribute of an `iframe` in `TalkLayout.tsx`, allowing for arbitrary execution via `javascript:` or `data:` URIs.
**Learning:** Next.js and React do not natively sanitize strings passed to `iframe` `src` attributes. Returning unvalidated fallback URLs from utility functions can expose XSS vulnerabilities. We should always explicitly validate protocols of URLs meant for `iframe` `src` using native `URL` parsing, as standard regex checks can sometimes be bypassed or insufficient.
**Prevention:** Use the `new URL(url, base)` constructor to parse and explicitly allowlist secure protocols (e.g., `http:` and `https:`) before using untrusted input in sensitive HTML attributes. Ensure empty strings and root-relative paths are also correctly handled.
